# AMOS Desktop 1.0.54

AMOS keeps recent tool results in context, reducing repeated work after it has already saved or inspected an asset. Tasks that hit a repetition, budget or recovery limit now finish as interrupted and retain their restart checkpoint instead of appearing completed.

Hosted landing-page work now follows a bounded plan, review and repair cycle. AMOS checks saved source against the current site manifest, reads the Platform's form-validation report, and reviews the result with the selected model. When a usable private preview and desktop browser are available, it also checks desktop and mobile layout geometry, broken images and page links. Existing pages require readable current source before an overwrite. A short final response separates saved work from anything still needing verification and returns the known private preview link.

The activity panel keeps the current work stage visible through model and tool updates. Cancellation, recovered sessions and partial results retain the correct task state. Local receipts and learning episodes distinguish a completed response from a verified outcome.

The hosted-site checks depend on compatible Platform tools. Source and layout checks do not establish end-to-end lead delivery, marketing attribution or visual design quality; those limitations remain visible in the result. This release does not change hosted model weights or publish pages automatically.

Validation: the implementation passed 1,050 tests, Node 22 and Node 24 CI, static checks and the Windows installer smoke check. Official release packaging verifies signed Windows installers and notarizes the macOS builds.
